1. Purpose & scope

One pipeline, start to finish

This script proves one thing end to end: that a system with nothing configured can be taken all the way to a real grade recorded against a real enrolled student, with every module along the way pulling correct data from the one before it. It's narrower than the full Registrar Training Flow UAT — that document tests every screen the Registrar role has, including documents, certificates, and reports printed after a grade exists. This one stops at the moment the grade is posted, because that's the line the request was scoped to: system config to inputting grade.

Every function below states two things instead of one "expected result": what a Pass looks like, and what a Fail looks like. A tester shouldn't have to infer failure from the absence of success — if the actual result doesn't match Pass, check it against Fail and record which one it actually was.

2. Pipeline map

Four days, each one only possible because the last one passed

Curriculum can't be built without a program. Scheduling can't happen without a published curriculum, a room, and a faculty member. A student can't enroll without a schedule to enroll into. A grade can't post without an enrolled student in an open grading period. That's the whole pipeline, in the order it has to happen.

7. Sign-off

What "the pipeline works" means

This script is accepted once all 48 rows read Pass, tracing one unbroken path from an empty Configuration screen to a grade sitting correctly in the Student Grade File. Because every day's data feeds the next, a Fail on an earlier day should pause testing on whatever downstream row depends on it rather than being tested against broken data.
