1. Purpose & scope

Why this guide exists

This guide walks through the Registrar's work in the order it actually happens on screen — from the System menu, through Academics, to Student Records, Faculty, and Reports. It is written for Registrar-office staff learning the system, and for anyone reviewing how the office's work is organized from start to finish.

The Registrar is the operational center of the system. No other role can set up programs and curricula, open or close an academic term, build class sections, or give grades their final sign-off. Every other portal — Student, Faculty, Parent, Applicant — depends on decisions made here.

2. Roles & access

Who else uses the system, and how access is controlled

The system serves five kinds of users, each with their own sign-in page and portal. Registrar is the administrative role — it can see and manage more of the system than any other account type.

RolePortalRelationship to Registrar
RegistrarRegistrar dashboardOwns academic structure, enrollment, grading sign-off, term scheduling, and system configuration.
FacultyFaculty portalSubmits grades and attendance into records the Registrar reviews and finalizes.
StudentStudent portalAccount created by the Registrar; views the records the Registrar maintains.
ApplicantApplicant portalPre-student stage; the Registrar reviews applications and admits new students.
ParentParent portalRead-only view of a linked student's records.

Beyond signing in, individual screens can be switched on or off per staff member. A senior registrar might be able to close an academic term, while a records clerk can only view and print documents.

Where to configure it

System > Access Management > User Accounts — turn specific screens on or off for each staff member.
System > Access Management > Report Access — control who can generate which reports.

3. Signing in

The Registrar sign-in page, and the password reset every new account goes through

ItemWhat happens
Sign-in pageA dedicated Registrar sign-in page, separate from the Student, Faculty, and Parent pages.
After signing inYou land on the Dashboard automatically.
If sign-in failsThe system checks your username and password, then confirms the account is properly set up as a Registrar account. If the account isn't linked correctly, you're signed back out with an "account not linked" message — contact your System administrator to fix it.

Any account newly created by the Registrar — a new staff member, or a student added to the system — is required to set a new password the very first time they sign in. The system won't allow the account to move on to any other screen until that's done.

4. Day-one checklist

The shortest path from an empty system to "a student can be graded"

This is the direct answer to "what needs to happen first, end to end, to start using the system." Each step below depends on the one before it — skipping ahead simply won't work, because the next screen has nothing to draw from yet. Steps 1–8 happen once, when the system is first set up. Steps 9–13 happen at the start of every term.

  1. Set the academic calendar basics
    School year and semester settings, grade posting windows, and document signatories. System > System Config > Configuration and Academic Calendar.
  2. Set up Departments
    A program can't be created without a department to belong to. Faculty > Departments.
  3. Create at least one Program
    Each program needs a unique code and a department. This is the foundation everything academic builds on. Academics > Curriculum > Program File.
  4. Build the Course File
    The catalog of subjects a curriculum is built from. Academics > Curriculum > Course File.
  5. Build a Curriculum for the Program
    Draws directly from the Program and Course File created above — it can't be built without them. Academics > Curriculum > Curriculum File.
  6. Route the Curriculum through approval and publish it
    Signed off in order: Department Head, Dean, Registrar, Academic Council. Nothing further can be built until it's published.
  7. Add Rooms
    Needed before class schedules can be generated. Academics > Term Setup & Scheduling > Room File.
  8. Create Faculty accounts
    Needed before a class can be assigned a teacher. Faculty > Create Faculty.
  9. Open an Academic Term
    On a brand-new system there's no earlier term to close first, so this is the one time a term can be opened without that requirement. Academics > Term Setup & Scheduling > Close/Open Term.
  10. Create Section Offerings
    Builds the actual class groups for the term, pulling the subject list from the published Curriculum. The system won't let you create a section if that curriculum hasn't been published yet. Section Offering.
  11. Prepare the Class Schedule and assign Rooms & Teachers
    Class Schedule Preparation, then Generate & Assign Rooms and Generate & Assign Teachers.
  12. Add Students
    Add students directly under Student Records > Enrollment List. Each new student automatically receives a sign-in account.
  13. The system is now ready for the term
    Faculty can record attendance and submit grades, and the Grading Sheets approval flow becomes active.

5. Process map

Seven stages, one recurring cycle

Setting up the academic structure is mostly one-time work, repeated only when a new program is introduced. Admissions through Reporting & Close repeat every academic term, and the last stage feeds straight back into the next term's setup.

System Setup
Calendar, staff accounts, grading rules.
2
Academic Structure
Departments, Programs, Course File, Curriculum, Rooms.
3
Admissions

4
Term & Sections

5
Enrollment
Enroll students, maintain their records.
6
Grading
Faculty submit → Dean approves → Registrar finalizes.
7
Reporting & Close
Certificates, transcripts, close term, open next.

8. Admissions

Applicant review through admission as a Student

Current system note

The Admissions menu is not currently shown in the Registrar's navigation in this environment. Until it is switched on, new students are added directly under Student Records > Enrollment List (see Stage 5). The steps below describe the designed admissions process, for reference once it becomes available.

TaskWhere it lives
Configure requirements, document checklist, exam categoriesAdmissions > Lookups
Review applicant queueAdmissions > Applications > Application List
Record exam schedule, result, interview outcomeAdmissions > Applications > Exam Schedule / Exam & Interview Scheduling
Review submitted documentsAdmissions > Applications > Document Submission
Approve or reject an applicationAdmissions > Applications > Approval Status
Admit approved applicants as StudentsAdmissions > Applications > Application List
What admitting an applicant does

Admitting an applicant generates a student number, copies their name and program preference from the application, and creates a sign-in account with a temporary password that must be changed on first login.

9. Term setup & sections

A new academic term can only be opened once the current term has been formally closed. On a brand-new system there's no earlier term to close, so this is the one exception.

11. Grading

The Registrar signs off last, never first

Grades never move directly from a faculty member to being official. Each class moves through the same three stages, forward only, unless sent back:

TaskWhere to find it
Review and act on submitted grades (approve, finalize, or reject)Faculty > Grading Sheets
Bulk-import grades from a spreadsheetFaculty > Upload Grades
Process a student's grade correction requestStudent Records > Student List (student's academic record)
Track incomplete grades and deficienciesAcademics > Grading Setup > Incomplete & Failing / Deficiency
Correct a grade directly (exception path)System > Grade Override
Use sparingly

Grade Override bypasses the normal Faculty → Dean → Registrar approval chain entirely, and every use is recorded for later review. Reserve it for correcting genuine errors after the fact, not for routine grading.

Hard rule — closing a term

The system checks for unresolved issues — such as incomplete grading — before it will allow a term to be marked closed. Every closure and re-opening is logged for later review.

Once a term is closed, it can be reopened for the next cycle. Promotion Readiness and Generate Academic Setup can carry class and student information forward from the closed term automatically, rather than rebuilding everything by hand.

14. Glossary

TermWhat it means
ProgramAn academic degree or course offering (for example, BSCS), set up under a department.
CurriculumThe subject plan for a program and school year. Goes through a four-step approval process and must be published before it can be used to build class sections.
Course FileThe catalog of subjects a curriculum is built from.
Section OfferingA specific class group (for example, "BSCS 1-A") created for a program, year level, and term.
Academic TermA school year and semester combination, moving through Draft, Active, Closed, and Archived stages.
Grading statusWhere a class's grades stand in the approval flow — submitted, approved by the Dean, or finalized by the Registrar — or sent back for correction.
ApplicantA prospective student in the admissions process, who becomes a Student once approved and admitted.
This guide reflects the menus and workflow available to the Registrar role as of the date above. For questions about access to a specific screen, contact your System administrator.
